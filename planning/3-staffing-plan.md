## 5. Communication and control

- Short team meeting or chat once a week to review progress.
- All files are kept in one GitHub repository; each deliverable is committed when finished.
- Problems and decisions are shared in the team chat; unresolved questions go to the professor.
- Before submission, every member reads the SRS and RTM and runs the tests once so each can answer questions about the project.

## 6. Staffing risks

| Risk | Mitigation |
| --- | --- |
| One member does more work than planned | Weekly review of the effort table; tasks reassigned through the RACI matrix |
| A member is absent near the deadline | Documents and code are on GitHub, so any member can continue |
